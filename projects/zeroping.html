ZeroPing — PHP Framework

A modern PHP MVC framework written from scratch with zero third-party runtime dependencies — router, DI container, ORM, validation, cache, queue, scheduler and CLI all built by hand, and published on Packagist.

Built by RIN Nairith, software developer in Phnom Penh, Cambodia.

The problem

Most “lightweight” PHP frameworks still pull in a third-party ORM, container or router, so you inherit a tree of packages you never chose and can’t easily read.

ZeroPing set out to prove a complete, familiar framework could be built from first principles — readable end to end, with nothing hidden in vendor code — and to deeply understand how frameworks like Laravel work by building one.

By the numbers

What I built

MVC + DI

Service container, service providers and a middleware pipeline, all written from scratch.

Routing

Static and dynamic routes, groups, prefixes, named routes and route caching.

Active Record ORM

Relationships, query builder, migrations and seeding.

Security

CSRF protection, encryption, hashing and rate limiting built in.

Queue & scheduler

Background jobs with sync and database drivers plus a task scheduler.

`php zero` CLI

Code generators, route listing, environment doctor, debug toolbar and a dev server on port 1437.

Every layer hand-written

Router, container, ORM, validator, cache, queue and encryption share one coherent style because they were designed together — and anyone can trace a request from entry point to response.

Zero configuration to run

Sensible defaults are baked in: php zero new my-app then php zero serve gives a working app. You only configure what you choose to change.

Tested across the PHP matrix

GitHub Actions runs the PHPUnit suite on PHP 8.1, 8.2, 8.3, 8.4 and 8.5 so the framework stays compatible as PHP evolves.

Shipped like a real package

Published on Packagist for composer create-project, with Docker + Nginx deployment to AWS EC2 for the documentation site.
